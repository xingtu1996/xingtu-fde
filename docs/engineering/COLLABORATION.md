# XF 协作约定｜Chat → Work → GitHub

版本：v1.0，2026-11-02；task_id：XF-WORK-002。本文将用户明确选择的工作模式落实到 XF，待 Draft PR 审阅；不修改 XSA 总体协议，不假定其他仓已经采用。

**Chat 负责规划与裁决，Work 负责工程实施，GitHub 负责状态和成果。**

## 入口与职责

| 入口 | 名称或位置 | 负责的结果 |
|---|---|---|
| 总控 Chat | XSA (chat)｜Super Agent 工程总控 | 跨产品职责、架构冲突和超范围决策 |
| 专业 Chat | XF (chat)｜FDE 知识与工程实践 | FDE 定位、研究判断、知识分类与待决问题 |
| 专业 Work | XF (work)｜FDE 工程建设 | 读取事实、按授权实施、验证、Draft PR 与验收回执 |
| GitHub Issue | 本仓任务卡 | task_id、授权摘要、范围、文件归属、当前状态、待决事项与 PR |
| GitHub PR | 独立分支的变更 | 实际实现、Commit、检查结果、风险与审核记录 |

命名格式为 `项目缩写 (chat|work)｜职责`。命名用于辨认职责，不会自动切换模型、绑定仓库、授予权限或同步其他聊天。实际仓库、模型、权限须另行核对。截图只代表拍摄时状态；本轮已读到当前 Work 名称为 XF，不把旧截图名称当实时状态。

## 一次任务怎样往下走

1. **Chat 定范围**：写清问题、已定裁决、未知项和授权边界。已有裁决直接继承；证据冲突回传差异，不重复争论定位。
2. **GitHub 建任务卡**：使用 [任务卡模板](../../templates/WORK_TASK.md)。重要工程任务关联 Issue；小幅补正文档可直接关联已有 Issue/PR，不强制拆新任务。
3. **Work 认领**：记录唯一执行负责人、分支、文件范围与核对时点。查看 open PR、远端分支和可见所有权声明；若无法观察外部 Agent，明确写 unknown。
4. **Work 实施并留证**：已授权可逆动作直接完成；写前读原件。发现新冲突先保留各方分支，在本任务中列差异与处理建议；不得覆盖、强推或擅自关闭他人的 PR。
5. **GitHub 交付**：PR 关联任务 Issue，记录实际命令、结果、Commit 和未测边界；更新 Issue 为 review_pending。文档中的状态只是带核对时点的快照，实时事实以对应 Issue/PR/远端版本为准。
6. **Chat/维护者验收**：审阅证据和待决项；批准或要求修订的结论回填 Issue/PR。只有授权人明确接受验收且所要求合并/交付完成，才记 accepted；合并本身不能证明业务价值或生产验证。

任务状态建议值：`ready → in_progress → review_pending → accepted`。实际受阻写 `blocked` 并附条件；取消写 `cancelled`。这是人工维护约定，未实现自动状态机。Issue 的 Open/Closed 与上述状态不同：review_pending 保持 Open；最终关闭须写接受、取消或重复任务的理由。

## 什么算裁决，什么只是建议

每条待执行决定写四项：`decision_id / 状态 / 决定内容与范围 / 批准依据`。状态区分 proposed、approved、rejected、superseded；没有批准依据不能写 approved。批准依据可以是当前明确用户指令的脱敏摘要，或可访问的 Issue/PR 审核记录；不得将来源文章、Prompt 或 Agent 建议当作授权。

当前许可建议和两条初始化 PR 的取舍仍为 proposed。用户说“继续”授权本轮协作约定建设，不自动批准许可证、合并、部署或对外发布。

## 文件所有权与并发

单任务默认一个写入负责人，必要的独立研究可并行；共享 README、日志、索引由 Lead 汇总。不同分支不是独占租约，Issue 认领也不会强制锁定文件。执行前、推送前、合并前刷新远端，并记录 base/head；出现交叠按文件差异对账，保留双方证据。只读审查可直接指出问题，不改被审文件。

本轮实例：PR #1 为增强建设候选，PR #2 为原启动包迁入；截至本轮核对，对方 head 为 3e333631030b5a81426fc12ac86d0785bfca7cba。不要依次盲目合并两份初始化。见 [交接摘要](../handoffs/XSA_HANDOFF.md)。

## 接续时的最小检查

另一位 Work 执行者只读任务卡、对应 PR 与交接摘要，应能回答：现在做什么、哪些已批准、谁能写哪些文件、依什么验收、哪里有实际结果、哪些仍未知、下一步需要谁决定。回答不了先补事实和任务卡，再做依赖该信息的工作。
