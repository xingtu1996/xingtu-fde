# Model & Agent Routing

本文件是任务建议，不会改变 ChatGPT Work 的实际模型选择，也不修改全局 config.toml。下列名称来自本任务用户指定与当前子 Agent 工具可选项，不填造 API 模型 ID。

| 任务 | 推荐模型 | 推理强度 | 升级条件 |
|---|---|---|---|
| 首轮架构继承、知识分类、跨仓裁决 | GPT-6.1 Sol | High | 证据冲突或跨产品职责争议可建议 Astra / Medium |
| 来源核验、文献与跨仓检索 | GPT-6.1 Sol | Medium | 来源相互冲突时 High |
| 索引脚本、Markdown、模板与工程实现 | GPT-6.1 Terra | Medium | 复杂实现或权限边界用 Sol / High |
| 证据、隐私、版权和回归审核 | GPT-6.1 Sol | Medium | 高风险未决结论用 High |
| 日常小幅文档更新 | 当前可用 Sol 或 Terra | Medium | 有新风险再升级 |

## 已验证与建议的区别

2026-11-02 主任务本地 turn_context 记录 `gpt-6.1-sol`、`high`；这是会话运行元数据，未公开原始日志。两次 spawn 请求明确选择工具列出的 `gpt-6.1-sol` / `medium` 并获得任务回执；已另行核对两份子任务 turn_context，实际均为 `gpt-6.1-sol` / `medium`。运行日志保留本地，不公开其中的私人路径或会话原文。

Terra 与 Astra 在当前工具模型清单可选，但本轮未调用或做效果对比。未验证自动路由、生产编排或任何模型的成本优势。Token、账户额度、费用若不可读取均写 unknown；不把推算当作官方计费。

## 分工与文件所有权

Lead 拥有根说明、docs/engineering、交接、practice、templates；Research 仅拥有 registry/；Quality 默认只读。每项并行工作先登记 MAINLINE_LEDGER.md，路径交集为空后再启动；禁止不同 Agent 同写同一 README、索引或日志。共享文件由 Lead 汇总，不自动提交或合并。

适合子 Agent：独立只读来源核查、局部索引建设、独立质量审查。强依赖或少量单文件修改由主任务直接做。当前工具允许最多三个子 Agent，本轮只启用两路。

## 额度与回退

先复用已存在设计和卡片，再读需要的原件；研究只回传摘要与证据指针。已通过的检查无新变更不重复运行。不为凑角色增加 Agent，不因额度不可见估算官方用量。

模型不可用时保留当前可用模型并记录差异；优先降低并行数量、缩小任务范围。只有证据不足、重复失败或复杂争议时建议升档。平台不能切换时继续可验证的低风险工作，无法作出的裁决交回 Chat。
