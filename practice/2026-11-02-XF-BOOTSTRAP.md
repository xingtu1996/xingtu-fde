## 背景

Chat 完成产品定位及 18 文件启动包，但连接器不提供创建仓库接口，内容暂存在 XSA 隔离分支。Work 接续时先查 GitHub 和可见聊天：发现已有包，避免重新撰写同样的知识库。

## 方案与执行事实

1. 连接器与本机 GitHub 身份均先查目标仓，返回 404；再读取已有 PR、分支与聊天交接。
2. 经用户明确授权创建公开仓，建仓后确认只有初始 main，无其他 PR、Issue 和分支；远端权限包含 push/admin。
3. 备份初始仓；建立独立 feat 分支。只迁移 incubation/xingtu-fde 的文件，不导入 XSA 其他内容和提交历史。
4. HTTPS 克隆停滞，停止本任务克隆，改用 SSH fetch 成功。没有修改全局网络或 Git 配置。
5. Research 独占 registry/，Quality 只读，Lead 维护工程规范与交接；先登记台账再分派。
6. 用固定版本核对来源；更新已过期的“待建仓”文字，保留历史建设账本，避免把先前执行者归给当前 Agent。

## 原理与反例

Chat 定方向、Work 执行、GitHub 留审阅证据，三者通过任务 ID、分支和 PR 关联。名称只是识别约定，没有自动建立项目绑定或权限。可见聊天与进程检查也不能证明所有外部 Agent 都空闲，建仓及推送前仍需核对远端。

## 尚未证明的效果

没有测量这套模式节省多少时间、Token 或成本；没有真实客户数据或生产部署。许可证最终授权仍需维护者裁决。截图未作为本轮证据入库，不公开原始聊天或未经脱敏图片。后续可在相同任务上记录人工接续次数和返工原因，再评估价值。
